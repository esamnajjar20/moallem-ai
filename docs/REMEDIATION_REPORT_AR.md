## 1. ملخص التنفيذ

نُفذت إصلاحات في المسارات البرمجية التي أمكن إثبات عيبها من المصدر والاختبارات، مع إبقاء ضوابط الأمان والقرارات المفتوحة كما هي. لم تُفعّل تكاملات الإنتاج التي تتطلب موافقة مالك المنتج أو الخصوصية أو الأمن أو مسؤول Moodle.

### الإصلاحات المنفذة

| المجال | العيب | الإصلاح |
|---|---|---|
| API routing | مسارات المقررات والمهام كانت تسجل في FastAPI دون `/api/v1` رغم أن عنوان الخادم في OpenAPI ينتهي بهذه البادئة | تسجيل المسارات رسميًا تحت `/api/v1`، مع إبقاء المسارات القديمة كبدائل توافق غير ظاهرة في OpenAPI |
| Task response links | `status_url` و`events_url` كانتا تعيدان روابط جذرية لا تتوافق مع عنوان API الموثق | أصبحت الروابط تعيد `/api/v1/tasks/...` |
| Moodle course scope | كان بالإمكان طلب محتوى أي `course_id` باستخدام اتصال Moodle النشط دون فحص تسجيل الحساب المتصل في ذلك المقرر | قبل جلب المحتوى، ينفذ النظام فحص تسجيل المستخدم عبر `core_enrol_get_users_courses`؛ المقرر غير المسجل يرفض بـ`MOODLE_PERMISSION_DENIED` |
| Course-list semantics | اسم العملية `listTeacherCourses` يوحي بضمان دور المدرس، بينما Moodle function المستخدمة تعيد تسجيلات المستخدم ولا تثبت الدور | تغيير اسم العملية إلى `listEnrolledCourses` وتوضيح حدوده في OpenAPI والوثائق |
| File provenance | كان `get_course_contents` يستخرج ملفات Moodle، لكن `to_dict()` كان يعيد `source_ref_id: null` ويحذف مراجع الملفات، كما كانت API تعيد `source_refs: []` دائمًا | تمرير UUIDs لجميع الملفات إلى `source_refs`، وإرجاع بيانات وصفية آمنة لكل ملف داخل الوحدة |
| File security | يجب ألا تصل روابط التنزيل الداخلية أو رموز Moodle إلى عميل API | بيانات الملف المنشورة لا تتضمن `download_path` أو URL التنزيل أو أي token؛ مسار التنزيل يبقى داخل طبقة الخادم |
| Contract drift | لم يذكر عقد OpenAPI استجابة 503 التي تصدرها نقاط Moodle عند عدم تركيب خدمة القراءة | إضافة استجابة 503 إلى عمليتي قراءة المقررات، مع وصف واضح لقيد دور المدرس |

### حدود بيئة الفحص

- التشغيل المتاح استخدم Python **3.13.5**، بينما المشروع يطلب Python **3.12.16**.
- تخطت الاختبارات الـ45 تكامل PostgreSQL لعدم وجود `MOALLEM_TEST_DATABASE_URL` وقاعدة اختبار مجهزة بالترحيلات.
- استُبعد اختبار واحد (`test_docs_disabled_in_production`) لأن إنشاء محرك PostgreSQL في البيئة الحالية تعذر بسبب غياب مشغل `psycopg`، رغم أن الاعتماد معلن في `pyproject.toml`.
- لم تتوفر أدوات Ruff أو mypy أو Flutter في بيئة التنفيذ الحالية؛ لذلك لا أدعي نجاح lint أو type-check أو بناء تطبيق الهاتف.
- لم يتصل الفحص بخادم Moodle حقيقي، ولم ينفذ عملية نشر أو تعديل على Moodle.

## 4. الفجوات التي بقيت مفتوحة ولم أفعّلها عمدًا

هذه ليست إصلاحات يمكن اتخاذها بأمان عبر افتراضات برمجية؛ بعضها يتطلب موافقات أو أسرارًا أو خدمات خارجية غير موجودة في الحزمة.

| الفجوة | لماذا بقيت مفتوحة | ما يلزم لإغلاقها |
|---|---|---|
| إثبات أن المقرر مقرر تدريس للمعلم | `core_enrol_get_users_courses` يثبت التسجيل فقط ولا يعيد دور المستخدم | حساب مدرس تجريبي على Moodle staging، ودليل capability أو وظيفة Moodle موثقة ومختبرة |
| إدارة اتصالات Moodle عبر API | لا توجد بعد عمليات HTTP للتسجيل/القائمة/التفاصيل/الفصل/التحقق/تدوير الرمز | تنفيذ Connection Management API مع idempotency وتخزين سري ذري، ثم اعتماد صلاحيات DEC-027 وقرار مشاركة الاتصالات |
| تفعيل اتصال Moodle تلقائيًا | النقل والمحلل موجودان لكنهما opt-in، وADR-020 وضوابط الخروج الشبكي غير معتمدة | موافقة egress، firewall allow-list، واختبارات staging حقيقية |
| إنشاء الاختبارات بالذكاء الاصطناعي | لا توجد معالجات CREATE_QUIZ إنتاجية ولا مزود معتمد | اعتماد ADR-018 ومزود/نموذج/منطقة وميزانية، ثم بناء handler يقرأ مصادر المقرر ويولد مسودة موثقة |
| مراجعة واعتماد ونشر الاختبار | لا يوجد بعد تدفق متكامل للـ draft والـ approval وMoodle write/verify APIs | نماذج مسودة ونتيجة محفوظة، واجهات snapshot/revision/approval/cancel/result، ثم اعتماد وظائف Moodle الكتابية |
| AI budgets وUNKNOWN reconciliation | `DenyAllAIExecution` هو الافتراضي ولا توجد خدمة ميزانية/حجز/تسوية إنتاجية مكتملة | محاسب ميزانية ذري لكل مؤسسة ومهمة، تسوية الاستخدام، ومعالجة نتائج المزود المجهولة |
| خدمات تخزين وفحص وتحليل الملفات | العملاء موجودون، لكن object storage وmalware scanner وsandbox extractor غير منشورة | نشر الخدمات والتحقق من mTLS وربط tenant/file/policy واختبارات عزل مستقلة |
| RAG دلالي | `ContextBuilder` يتحقق من مراجع جاهزة، لكنه ليس نظام embeddings/vector search | اعتماد مخزن/محرك الاسترجاع، الفهرسة والتحديث والحذف وقياس جودة الاسترجاع |
| تطبيق المعلم Mobile | Flutter حاليًا shell تأسيسي؛ لا توجد شاشات سير عمل كاملة | بناء المصادقة والاتصالات والمقررات وإنشاء المسودة والمراجعة وتتبع المهام بعد تثبيت عقود API |
| لوحة ويب وإدارة وتشغيل | لا توجد واجهة Web ضمن الأرشيف | تحديد نطاقها وأدوارها ثم بناءها فوق API المعتمد |
| جاهزية PostgreSQL والإنتاج | لم تُشغّل اختبارات PostgreSQL على قاعدة حقيقية في هذه البيئة | Python 3.12.16، PostgreSQL قابل للتخلص، `alembic check` وupgrade/downgrade/re-upgrade والاختبارات المتزامنة |

## 5. ضوابط الأمان التي بقيت كما هي

- بقي `DenyAllPolicy` الافتراضي كما هو؛ لم أفتح صلاحيات `TEACHER` تلقائيًا.
- بقي `DenyAllAIExecution` كما هو؛ لم يتم إرسال بيانات المقررات إلى أي مزود AI.
- لم يتم تسجيل handler وهمي لمهمة `CREATE_QUIZ` ولم يتم الادعاء بأن العامل ينشئ اختبارات.
- بقيت خدمات الملفات الخارجية غير مفعلة.
- لم تُستخدم مفاتيح تطوير لتشفير أسرار إنتاجية.
- لم أضف أي سر أو عنوان Moodle أو إعداد نشر افتراضي غير مقدم من مالك المشروع.

## 6. قرار الحالة بعد الإصلاح

- **إصلاحات API وMoodle read/provenance:** منفذة ومحلية الاختبار.
- **P3:** تحسن في التحقق من نطاق قراءة المقرر وتمرير provenance، لكنه لا يزال غير مغلق بسبب غياب إثبات دور المدرس وبيانات staging.
- **P2/P4/P5:** ما تزال جزئية وفق البوابات والقرارات المذكورة أعلاه.
- **المنتج الكامل:** غير جاهز بعد للاستخدام الفعلي للمعلم أو للنشر الإنتاجي.

لا ينبغي تفسير نجاح اختبارات المنطق المحلية على أنه تكامل Moodle حي أو جاهزية تشغيلية أو اعتماد أمني للإنتاج.
