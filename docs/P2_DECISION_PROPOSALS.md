# P2 — مقترحات القرارات المفتوحة (جاهزة للتوقيع)

**الحالة: PROPOSED.** لا يُعدّ أي بند مغلقاً قبل توقيع المالك المذكور. كل توصية قابلة للتراجع قبل وجود بيانات حقيقية.

## ADR-017 — الهوية والجلسات (Product + Security)
**اختيارك: Auth0** (مسجَّل هنا كاختيار المزوّد؛ التوقيع الرسمي للمالكين ما زال مطلوباً).
**التوصية:** عدم بناء مصادقة داخلية؛ مزوّد OIDC خارجي.
- Access token قصير (≤ 15 دقيقة) يُرسل كـ Bearer؛ التحقق من issuer وaudience وانتهاء الصلاحية على الخادم.
- Refresh token معتم، يُدوَّر عند كل استخدام مع كشف إعادة الاستخدام (reuse ⇒ إلغاء السلسلة كلها).
- جدول جلسات على الخادم للإلغاء الفوري؛ ربط `(issuer, sub)` بمستخدم عالمي واحد.
- MFA إلزامي لأدوار الإدارة؛ للمعلّم يُقرَّر لاحقاً.
- **ما يفتحه:** استبدال `NoAuthenticator`. **ما لا يحسمه:** اختيار المزوّد التجاري.

## DEC-026 — مشاركة موقع Moodle بين المؤسسات (Product + Architecture)
**التوصية:** سجل موقع **لكل مؤسسة** (بلا مشاركة) في MVP.
- `UNIQUE(tenant_id, base_url)`؛ بيانات الاعتماد لا تُشارَك أبداً.
- المشاركة لاحقاً عبر منح صريحة (grants) دون هجرة بيانات.

## DEC-027 — مصفوفة صلاحيات المعلّم v0 (Product + Security)
**التوصية:** منح صريح فقط؛ ما عداه مرفوض. دور Moodle وحده لا يكفي: يُفحص capability بعد قرار التطبيق.

| الإجراء | TEACHER | ملاحظة |
|---|---|---|
| `course.read` | نعم | ضمن المؤسسة |
| `connection.read` / `connection.validate` | نعم | اتصالات عضويته |
| `task.create` / `task.read` | نعم | مهامه فقط (actor_membership) |
| `task.cancel` | نعم | مهامه فقط؛ DEC-042 |
| `task.approve` | نعم | صاحب المهمة فقط، مع حداثة Snapshot |
| `connection.credential.*` | نعم | صاحب الاتصال فقط |
| أي شيء آخر / أي دور آخر | لا | |

## DEC-032 — استراتيجية العزل (Backend + Security)
**التوصية:** دفاع متعدد الطبقات، بهذا الترتيب:
1. مستودعات مقيّدة بالمؤسسة (منفَّذة كواجهة في `domain/scoped.py`).
2. مفاتيح خارجية مركّبة `(tenant_id, id)` في كل جدول مؤسسي.
3. RLS اختياري لاحقاً بـ `SET LOCAL` لكل معاملة، بشرط اختبار pooled connection صراحةً.

## ما لا يُغلق بمجرد القرار
- P2-03 الكامل يحتاج DB وworker وcache وstorage (DEC-030/031 وP4).
- P2-02 يحتاج اختيار Secret Manager؛ الواجهة جاهزة (`domain/secrets.py`).

## P2-02 — GitHub Secrets ليس مخزناً تشغيلياً لتوكنات Moodle
GitHub Secrets **للكتابة فقط** ولا يوفّر API لقراءتها من التطبيق وقت التشغيل، ولا يصلح لتخزين توكن لكل اتصال ينشئه المعلّمون ديناميكياً. صالح لـ: أسرار CI/النشر (مفتاح التشفير الرئيسي، إعدادات Auth0 غير العامة، مفتاح HMAC).

**التوصية العملية:** تشفير مغلَّف (envelope) داخل التطبيق: AES-256-GCM لكل توكن، ويُخزَّن النص المشفّر + nonce + رقم نسخة المفتاح في PostgreSQL، ومفتاح التشفير الرئيسي (KEK) يأتي من متغير بيئة على Railway (يُحقن من GitHub Secrets أو من لوحة Railway). تدوير المفتاح بتخزين رقم النسخة. يتطلب إضافة `cryptography` إلى القفل (غير ممكن دون شبكة). **لم أنفّذه**: لا أكتب AES بنفسي.
